The gap

Signatures prove who built it. Not what's inside.

A signed SBOM is an ingredients list. But does the chip actually contain those exact modules, byte-for-byte? Most pipelines never check — they trust the list. That's the hole.

Membership check — the usual one

“Is every declared module present, by ID?”

A same-GUID trojan keeps a module's identity but swaps its code. The inventory still looks complete. Fooled.

Byte-integrity — what this adds

“Do the shipped bytes hash to what was declared?”

The fingerprint comes from the bytes themselves. Change the code and it changes. Caught — release blocked.

The model

Evidence-centric attestation → one gated policy → a signed verdict

Producers derive facts from real artifacts and sign them. The gate only decides — it ANDs every check. Nothing is trusted that isn't independently derived.

The three core checks

Reconcile · byte-integrity · CHIPSEC — three questions, three levels

"Does the firmware match its bill of materials?" splits into three different questions. Most tools ask only the first.

① Reconcile composition

Are the declared modules present? Carve the real image; match every module by its ID (GUID).

catches a missing module — or an undeclared one that shouldn't be there.

reconcile-membership → SI-7 · CM-8(3)
② Byte-integrity content

Do the shipped bytes match? Hash each module's actual PE32 bytes; compare to the SBOM's declared hash.

catches a same-GUID trojan — same ID, swapped code — that membership misses.

component-byte-integrity → SI-7(1) · SR-4(3)
③ CHIPSEC platform

Are the chip's defenses on? Assess platform-firmware protections on the target.

catches BIOS-write-protect / SMM / Secure-Boot misconfiguration on the target. SPI-lock & SMRR need real silicon — they report N/A, not pass.

chipsec-posture → SP 800-193 §4.2 · SP 800-147 (write-protect)
the right parts are present (reconcile) · the parts are genuine (byte-integrity) · the chip's defenses are on (CHIPSEC) — three complementary layers, one gate

The two novel controls

Where this goes past the standard stack

Byte-integrity · reconcile-to-bytes

Prove the chip runs the declared code

The hard part was PEI modules: they're rebased in flash (addresses shifted), so a naïve hash never matches. The relocation table records exactly what shifted — so it's reversible.

shipped (rebased)d75272…946710a8 ✗
un-rebase → compare3b830c…7480d6f7 ✓

DXE directly (111) + PEI/SEC via un-rebase (11) → all 122 code modules verify. The 123rd file, ResetVector, is a raw blob with no PE32 — covered by membership, not byte-integrity. A real tamper changes code the relocations don't cover, so it still fails.

Firmware-digest anchor

Bind the evidence to these bytes

Three independently-sourced digests of the firmware must agree — so the whole evidence set is about the image you're about to flash, not a document someone handed you.

① build-time SBOM digestD
② reconcile's own re-hashD
③ deployed .fd (flash-time)D

A consumer CLI re-runs this on their firmware and degrades honestly to MISSING_EVIDENCE when there's no attestation.

Compliance, honestly

Mapped to real controls — not "we comply with everything"

The signed verdict is scored per-control across seven frameworks. Each check is tagged with the exact control it earns; nothing claims whole-framework compliance.

✓SLSA v1.0 — Build L2 ✓NIST SSDF (800-218) ✓NIST SP 800-53 ✓SP 800-193 (firmware) ✓OpenSSF S2C2F ✓EU CRA · BSI · CISA

e.g. byte-integrity earns SI-7(1) "integrity checks over components" — the real thing (the bytes match), not merely "a hash exists".

Honest scope

What's enforced, what's evidence, what's next

ENFORCED — hard-blocks a release

  • 24 signed checks incl. byte-integrity + CHIPSEC + binary-hardening
  • SLSA L2 provenance — GitHub-generated, verified in CI (gh attestation verify); L2 = platform-generated, not third-party-audited
  • membership + byte-level integrity, 122/123 code modules

EVIDENCE — produced, mapped

  • SAST (CodeQL), OpenSSF Scorecard
  • CDX↔SPDX / coSWID interop
  • controls satisfiable but not yet a gate rule

OUT OF SCOPE — named, not hidden

  • TE-format / compressed module sections
  • runtime / measured-boot attestation
  • offline DEV_ASSUME opt-ins (never in CI)

Firmware-derived evidence is produced offline against the real .fd and consumed (not regenerated) by CI. Every check has an isolating negative fixture; the producers and the assembler are unit-tested; a skip is never a pass.

Reference target: OVMF / edk2

Build-time SBOM generator (edk2 -Y SBOM) → FMMT carve + reconcile → byte-integrity → CHIPSEC → CVE/VEX → cosign keyless attest → OPA gate → signed SLSA VSA → a consumer CLI that verifies it against your own firmware. One engine — firmware → components → a verdict you can prove.
